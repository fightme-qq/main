# Аудиобиблиотека и аудиосистема

Документ описывает Этапы 3–4: как устроена библиотека ElevenLabs, как она
генерируется и проверяется, и как игра её использует. Звуки лежат в
`public/assets/audio/`, манифест — `public/assets/audio/manifest.json`.

## 1. Правила и безопасность

- Ключ читается **только** из переменной окружения `ELEVENLABS_API_KEY`. Он не
  записан ни в исходники, ни в `.env.example`, ни в конфигурацию Vite, ни в
  клиентский бандл, ни в отчёты.
- Генерация — локальный инструмент разработчика (`npm run audio:generate`).
  Браузер игрока никогда не обращается к ElevenLabs: все файлы лежат рядом с
  игрой.
- `.env` уже в `.gitignore`; ключ в репозиторий не попадает.
- Скрипт не перегенерирует существующие файлы без `--force`, повторяет запросы
  при `429/5xx` (до 4 попыток с нарастающей паузой) и не пишет заглушки: если
  аккаунт не поддерживает Sound Effects, генерация останавливается с ошибкой.

## 2. Каталог

`scripts/audio/catalogue.mjs` — единственный источник истины: 100 записей,
разложенных по категориям.

| Категория | Кол-во | Назначение |
|---|---|---|
| `environment` | 15 | лес день/ночь, ветер, туман, дождь, гром, пещеры, заброшенное место |
| `player` | 56 | 6 поверхностей шагов × 5 вариантов, бег/дыхание, прыжок, приземление, плавание, сердцебиение, урон, смерть, еда/питьё, бой, щит, лук, поломка инструмента, предметы |
| `world` | 23 | разрушение/установка блоков (камень/дерево/земля/стекло/металл/растения), удары, двери, контейнеры, огонь, крафт, механизмы, вода |
| `creature` | 23 | три роли существ (странник, охотник, скрывающийся) + общие реакции животных |
| `horror` | 13 | тихие акценты, шёпот, хруст ветки, шаги, стук, скрежет, рёв, шумовой эффект |
| `ui` | 6 | инвентарь, выбор, ошибка, крафт, экран смерти |
| `music` | 6 | день, сумерки, две ночи, пещера, меню |

Итого **142 файла**. Шаги генерируются по 5 вариантов на поверхность: при
спринте шаг звучит каждые ~0.34 с, и трёх вариантов не хватало — слышался цикл.

Промпт собирается из `subject` + общих негативных ограничений категории
(`PROMPT_SUFFIXES`): «no music, no voices, clean ending, no silence padding» и
т.п. Ограничения заданы один раз, чтобы не разъезжались по 100 записям. Длина
промпта принудительно ≤ 450 символов (лимит API): при переполнении сначала
отбрасывается подсказка о длительности, затем подрезается `subject` по границе
клаузы.

Ограничение сервиса: один запрос — от 0.5 до 30 секунд. Поэтому атмосферные
циклы по 30 секунд (в ТЗ допускалось 20–60).

## 3. Генерация

```powershell
# ключ только в текущей сессии шелла
$env:ELEVENLABS_API_KEY = "..."

npm run audio:generate -- --dry-run           # что будет сделано
npm run audio:generate -- --limit=5           # тестовая партия
npm run audio:generate -- --category=horror   # одна категория
npm run audio:generate -- --force --only=amb_forest_night_01
```

- Формат: `mp3_44100_128`. MP3 декодируется всеми браузерами; «сырой» Opus,
  который отдаёт API, не является Ogg-контейнером и не годится для
  `decodeAudioData`.
- Файлы: `public/assets/audio/<категория>/<id>.mp3`.
- После каждого файла атомарно обновляются манифест и отчёт
  `assets/audio/generation-report.json` (он не попадает в сборку).
- `loop: true` передаётся в API для атмосферных слоёв (сервис поддерживает
  бесшовный луп).
- Музыка (`api: 'music'`) идёт через отдельный эндпоинт `/v1/music`
  (`music_length_ms`, `model_id: 'music_v1'`, `force_instrumental`), а не через
  Sound Effects. Треки по 30 секунд, инструментальные.
- При ошибке 400 «text_too_long» генератор не падает: `promptFor` заранее
  подрезает промпт до 450 символов, а при переполнении отбрасывает подсказку о
  длительности.

## 4. Проверка качества

`npm run audio:qc` открывает headless Chromium, декодирует каждый файл через
`OfflineAudioContext` и измеряет:

- длительность (заменяет запрошенную в манифесте — API может вернуть короче);
- пик и RMS;
- долю сэмплов на полной шкале (клиппинг);
- тишину в начале и конце;
- нормализационную громкость `gain` (цель по категории, с потолком по пику),
  чтобы тихий шаг и громкий рык стартовали сопоставимо.

Пороговые значения: пик ≥ 0.02, клиппинг ≤ 0.2 %, ведущая тишина ≤ 0.6 с,
хвостовая ≤ 1.2 с. Отчёт — `assets/audio/quality-report.json`.

Проблемные файлы перегенерируются точечно с уточнённым промптом
(`--force --only=...`); после правок QC прогоняется заново.

Текущий результат: **142 файла, 12.29 МБ, 22 лупа и 120 one-shot'ов,
длительность 1–30 с, QC — 142 чистых, 0 предупреждений**. Восемь файлов пришлось
перегенерировать: два почти беззвучных (лесной день, удар по дереву), клиппинг
у близкого рёва, ведущая тишина у далёкого шёпота и у вечерней музыки,
хвостовая у звука крафта, почти беззвучный выстрел лука.
## 5. Аудиосистема

### Категории и громкость

Микшер: `source → voice gain → category gain → master → destination`.
Категории соответствуют слайдерам настроек: `ambient`, `blocks`, `weather`,
`player`, `creatures`, `horror`, `ui`, `music`. Для хоррор-микса добавлены
отдельные слайдеры `Player`, `Creatures`, `Horror events`.

### Загрузка библиотеки

`AudioManager.loadLibrary()` вызывается после первого пользовательского жеста
(разблокировка звука) и не блокирует старт мира:

- манифест валидируется строго (`normaliseManifest`); при ошибке библиотека
  отключается целиком, игра остаётся на синтезе;
- короткие one-shot'ы скачиваются и декодируются пачками по 6 (пик памяти
  ограничен);
- **циклы не декодируются**: 30-секундный стерео-файл — это ~10 МБ float-сэмплов
  на слой. Они играют через `HTMLAudioElement` +
  `MediaElementAudioSourceNode`, то есть стримятся и проходят через те же
  category/master gain.

### Ключи и варианты

Игровой код продолжает говорить `step.grass`, `break.wood`, `chest.open` —
перевод в файлы делает `src/audio/SoundLibrary.js`:

- `FILE_SOUND_MAP` — ключ → 1–3 файла-варианта; вариант выбирается случайно, но
  не повторяется дважды подряд;
- `FILE_LOOP_MAP` — ключ → файл цикла;
- `DIRECT_SOUND_IDS` — существа, хоррор-акценты, гром, удары инструментом и
  двери. Голоса трёх ролей уже привязаны к поведению через
  `src/entities/MobSounds.js`: обнаружение, погоня, атака, урон, смерть,
  наблюдение и исчезновение звучат позиционно;
- `FALLBACK_ALIASES` — если файлов нет (библиотека не сгенерирована), ключ
  откатывается на существующий синтезированный звук, поэтому смерть, крафт и
  сундуки не замолкают.

Манифест валидируется `normaliseManifest`: версия, формат, id, путь, категория,
флаг лупа, длительность и gain. Ошибка в манифесте отключает файловую
библиотеку целиком и оставляет синтез — это лучше, чем половина игры без звука.

### Тесты

- `npm run selftest:horror` — 75 проверок, из них 20 про аудио и темп: манифест
  валиден и полон, файлы существуют, категории/лупы совпадают с каталогом,
  каждый ключ имеет файл, каждый файл достижим, алиасы указывают на реальные
  звуки, промпты ≤ 450 символов, длительности в диапазоне API, у каждой фазы
  суток есть музыка, у шагов 5 вариантов, у прыжка/приземления есть записи.
- `npm run audio:browser` — headless Chromium: AudioContext запускается,
  манифест загружается (142 записи), декодируются one-shot'ы, ключи получают
  варианты, стриминговые лупы стартуют из кадрового цикла, играют шаги, прыжок,
  приземление, плавание и восемь боевых/интерфейсных ключей, слайдер
  `Creatures` доходит до своего gain-узла, позиционный звук идёт через
  `PannerNode`, ночь переключает музыкальный слой и режиссёр выдаёт событие,
  нет ошибок в консоли и ни одного неудачного запроса аудио-ассетов.

### Музыка

Шесть инструментальных треков по 30 секунд (`music_day_01`, `music_dusk_01`,
`music_night_01`, `music_night_02`, `music_cave_01`, `music_menu_01`) играют как
стриминговые лупы. `AudioManager.setMusicPhase(phase)` держит включённым ровно
один слой и кроссфейдит остальные за ~0.35 с; фазу выбирает режиссёр напряжения:

- `day` — спокойный фон исследования;
- `dusk` — нарастающая тревога (включается и на рассвете);
- `night` — два альтернативных трека, выбираются на сессию;
- `cave` — подземный гул;
- `menu` — тема меню, пока игра не идёт.

### Режиссёр напряжения

`src/gameplay/TensionDirector.js` — не «случайные скримеры», а расписание:

- ночью далёкие события идут каждые 22–52 с, в сумерках 38–78 с, в пещере
  40–85 с; чем глубже ночь, тем чаще;
- событие никогда не повторяется дважды подряд и всегда ставится в кольцо
  10–26 блоков вокруг игрока, поэтому слышно направление, а не «где-то»;
- сердцебиение поднимается от низкого здоровья и от ночи;
- в меню и на паузе события не играют, но музыка меню продолжается.

### Атмосфера

`AudioManager.updateAmbience()` при наличии библиотеки выбирает слои по биому,
времени и глубине (решение пересчитывается раз в 0.4 с, громкости сглаживаются):

- лес днём/ночью, болото — плотнее туман;
- пещера (ниже уровня моря на 22) — гул, капли, подземный ветер;
- открытая местность — лёгкий/сильный ветер в зависимости от высоты, ночи и
  дождя;
- дождь — кроссфейд `light → heavy` по интенсивности;
- постоянный низкий гул под всем остальным: 0.07 днём, 0.13 в сумерках, 0.18
  ночью — мир всегда звучит так, будто затаил дыхание;
- Nether/End и подводный мир остаются на синтезированных слоях.

### Пространственный звук

- Слушатель обновляется каждый кадр из камеры (`AudioManager.setListener`):
  позиция + направление взгляда, с рампированием, чтобы быстрый поворот не давал
  «zipper»-артефакт.
- `play(name, { position })` строит `PannerNode`: `distanceModel: 'inverse'`,
  `refDistance 2`, `maxDistance 48`, `rolloff 1.1`. Для существ и хоррор-акцентов
  используется `HRTF` (важно «спереди/сзади»), для дешёвых звуков — `equalpower`.
- `playLibrarySound(id, { position })` — точка входа для ИИ: существа и
  хоррор-события уже могут звучать в пространстве, как только появятся события.
- Затухание от стен пока не считается: параметр `occlusion` (0..1) есть в API, но
  вызывающая сторона должна передать его после лучевой проверки. Это делается
  вместе с механикой шума, где такая проверка всё равно нужна.

## 6. Ограничения

- Прослушать файлы «на слух» агент не может (модель без аудиовхода). Проверены
  формат, декодирование, длительность, пики, клиппинг, тишина и громкость;
  художественное качество и бесшовность лупов нужно оценить в игре.
- Существа, хоррор-акценты, удары инструментом, двери и дыхание после бега пока
  не привязаны к игровым событиям — это этап ИИ/шума и выживания. Файлы уже в
  сборке и играются по id.
- Дверь использует один ключ `door.toggle`, поэтому отдельные `open/close` файлы
  ждут разделения события.
